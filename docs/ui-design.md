# UI 与国际化设计规范

## 产品结构

用户要求“五大导航”但仅列出四个名称。本基线补入首页，形成 Home / Races / News / Data / Profile（首页 / 赛事 / 资讯 / 数据 / 我的）。这是待产品确认的可逆假设，不新增第六入口。当前页面只切换占位区域；后续再引入路由、深链和真实内容。

管理端为独立应用，后续左侧导航为内容、赛历、数据源、审核与审计。Phase 0 仅显示锁定状态，不提供假登录或可点击的写入操作。

## 视觉基线

深色赛车风格采用高对比背景、暖红强调、紧凑数据排版和较大标题。品牌仅使用原创文本 NOBI RACING，不含官方 F1 Logo、车队标识或未经授权摄影；目前无远程字体或图片请求。字体名称优先 Inter / Noto Sans SC，未随项目捆绑；缺失时使用系统字体，后续捆绑需记录许可。

权威 Tokens 在 packages/design-tokens/src/tokens.css，公共样式在 base.css。禁止在业务组件散布品牌色常量。

| Token 类别 | 约定 |
| --- | --- |
| 背景 | bg #0B0E14，surface #151B26，raised #202938 |
| 文本 | text #F3F6FC，muted #B0BBCF |
| 强调 | accent #FF624D，on-accent 使用深色文字 |
| 状态 | success #65D6A6，warning #FFD275；必须配文字/图标 |
| 交互 | focus #80CFFF；可见焦点环 3px，偏移 3px |
| 间距 | 4、8、12、16、24、32、48 px |
| 圆角 | 8px、20px |
| 正文 | 16px / 1.6；辅助文字至少 14px |
| 动效 | 150ms 快速反馈；尊重 prefers-reduced-motion |

## 布局与组件

手机 <600px 使用固定底部导航，含 safe-area-inset-bottom；桌面为最大宽度 1120px 的内容区。后续平板断点 768px、桌面 1200px 由内容需要添加，不仅以设备名称判断。以 320px、390px、768px、1440px 验证中英文，不允许横向溢出或裁掉导航文字。

按钮/选择器最小触控高度 44px，禁用状态应有原因文字。卡片包含标题、内容类型、来源、发布时间和可选授权徽标。赛程显示本地时间与赛事时区切换；数据表在窄屏改为可访问的横向滚动或卡片，列头语义保留。

未来所有业务页面必须具备 loading、empty、error、stale/offline 状态。加载骨架不模拟具体结果；错误提供重试与 traceId；空态不展示伪赛事；过期数据只有授权允许时显示更新时间和 stale 标记。

## 双语与无障碍

- 文案通过 packages/i18n/src/en.json 和 zh-CN.json 统一管理，键集合必须一致。技术品牌名、语言名称可保持原文。
- HTML lang 随切换更新。日期/数字用 Intl，禁止拼接英文日期或把时区硬编码为北京时间。
- 图标按钮须有本地化 aria-label，交互可键盘访问，阅读顺序与视觉一致。页面一个 h1，标题层级有序。
- 正文目标 WCAG AA 对比度 >=4.5:1，大字与非文字边界 >=3:1。离线测试验证核心文字/背景、强调文字和边界组合；不等价于完整可访问性审计。
- 未来 Mock 内容必须同时有可见 MOCK · 示例数据标记和 API provenance.mode=mock；不可仅用颜色区分。当前基线没有赛事夹具，状态接口明确 dataMode=mock。
- 用户有语言偏好时优先于设备语言；Phase 0 仅会话内切换，不声明已实现账户保存。
